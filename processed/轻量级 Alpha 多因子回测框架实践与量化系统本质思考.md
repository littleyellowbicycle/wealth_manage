# 轻量级 Alpha 多因子回测框架实践与量化系统本质思考

## 核心结论
> 该框架以 [[alphas]] 项目为主体逻辑，用 [[bt]] 替代 [[backtrader]] 完成批量多因子全市场回测，数据源采用 [[baostock]] 与 [[akshare]]，从而绕开 backtrader 添加基准困难、批量回测不便的痛点。作者从程序员架构视角指出，[[量化回测]] 本质上是对股票 K 线数据的 for 循环，[[量化交易系统]] 则是把循环替换为实时数据获取并对接交易接口，理解这一抽象比掌握具体框架更重要。

## 详细内容
## 一、框架构成与开源依赖

该量化研究框架整合了三个核心开源项目，并以两个免费数据源作为底层支撑。

**核心项目：**
- [[alphalens]]：Quantopian 出品的通用 [[Alpha因子]] 分析工具，用于因子 IC、分位收益等评估。
- [[bt]]：小巧简洁的 Python 量化回测框架，比 [[backtrader]] 更轻量，天然支持多策略并行回测，是本框架选择它而非 backtrader 的关键原因。
- [[alphas]]：[[Alpha101]] 与 [[Alpha191]] 因子的实现与测试仓库，作为框架主体逻辑来源。

**数据源：**
- [[baostock]]：证券宝，提供无需注册的证券历史行情与上市公司财务数据。
- [[akshare]]：基于东方财富页面的开源金融数据接口库。

## 二、使用流程

完整的因子研究流水线分为五步：

1. 运行 `datas.py` 下载股票数据（前/后复权需谨慎，原始数据准确性问题较大）。
2. 运行 `alphas101.py` 或 `alphas191.py` 计算因子值。
3. 在 `1.research.ipynb` 中使用适配后的 [[alphalens]] 分析因子表现。
4. 在 `2.1.bt.ipynb` 中基于 [[bt]] 完成回测，取代原项目的 backtrader 实现。
5. 在 `factorycompare.ipynb` 中计算历年因子收益与百分比排名。

## 三、bt 回测关键步骤

以单因子回测为例，核心流程为：

### 1. 获取股票与基准数据

从 [[baostock]] 获取沪深300成分股价格数据并做 pivot 整理；同时拉取 `sh000300` 作为基准。对价格做 `-1` shift 模拟次日成交，并用前值填充缺失。

### 2. 因子信号构造

调用 `alphalens.utils.get_clean_factor_and_forward_returns` 把因子与未来收益对齐，取 `factor_quantile == 10` 的资产作为多头持仓集合，将其 pivot 成布尔型的 [[调仓信号]] 表。批量模式下，可对所有因子（排除部分不可用编号）循环生成信号并存入字典。

### 3. bt 自定义策略

继承 `bt.Algo` 实现 `SelectTrade`，根据当日信号选取目标股票；策略栈为：`SelectTrade` → `WeighEqually` → `Rebalance`。基准策略使用 `RunOnce + SelectAll + WeighEqually + Rebalance`。

### 4. 全因子并行回测

`bt.run(*bt_list)` 通过星号解包一次性传入所有因子回测与基准回测对象，执行效率显著高于 backtrader 的串行实现，这也是选择 bt 的核心理由。

## 四、对量化系统的本质理解

作者早期使用过 [[聚宽]] 与 [[backtrader]]，后转向 C++ 实现的 [[wondertrader]]，才形成对量化系统较清晰的认知。

从架构师视角看：
- **量化回测系统**：本质是一个遍历股票 K 线数据的 `for` 循环，回调函数即为策略主体。
- **量化交易系统**：把 `for` 循环替换为实时行情推送，策略内对接交易接口下单。
- **极简形态**：甚至不需要框架，直接用数据库 + 定时任务生成信号表，再由交易程序扫描执行，与互联网公司的数据驱动决策流程本质无异。

高频系统会复杂得多，但中低频策略的核心抽象仍可归结为：数据获取 → 信号计算 → 订单生成 → 成交回报 的循环。
